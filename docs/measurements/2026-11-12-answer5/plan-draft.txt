DRAFT 2026-11-12T02:08:01Z: run plan for the answer-5 runs, written before any timed run. Not in force until the three
open fields below are filled in, the file is committed as plan.txt, and the owner gives the go-ahead.

open fields
  commit and APK: the commit the cloud session names after Codex's findings 1, 2 and 8 and the smoke faults are
    dealt with; the APK's sha256 is recorded here. The smoke check is repeated on that APK first.
  cooling value, Pixel 8: from the baseline procedure below, at the start of the first session.
  owner's go-ahead: date and words.

every run
  KVID_INDEX_MEASURE=corpus=mixed+notes=5000+<configuration>+edits=200+queries=200+pause=300
  fresh instrumentation process, same APK, model files as in Phase B. Screen on, launcher in front, phone at its
  charge limit and not charging (state recorded in each gate line; a run does not start while it charges).

configurations
  A  model=bge-fp32                 (baseline, 512 tokens)
  B  model=bge-fp32+maxTokens=256   (the only candidate whose quality passed)

unit and order (step 3, Pixel 8)
  The unit is a block of two runs, one per configuration. Order by block: AB, BA, AB, BA.
  At least three valid blocks, over at least two sessions; the fourth if the phone is available.
  A session is one attachment of the phone. A block that loses a run is repeated whole and reported as excluded.
  Roughly 45 to 60 minutes per run with its cooling wait, so a block needs about two hours of attachment.

cooling rule (fixed here; do not reuse either Phase B rule for the Pixel 8)
  Baseline at the start of each session: phone at its charge limit and not charging, launcher in front, screen on,
  nothing run by the driver for at least 20 minutes, VIRTUAL-SKIN read every 60 s.
  Idle level = median of the last 15 readings. Threshold = idle level + 0.5 C, rounded to 0.1 C.
  A run starts only at thermal status 0 with skin at or below the threshold; gate timer 2 hours.
  The threshold of a later session is computed the same way and recorded. If it differs from the first session's
  by more than 1.0 C the session is not run and that is reported. No other change to the rule; if the phone
  cannot reach it, the runs are not made.

exclusions (decided by these rules only, never by a result)
  another app in front before, during or after the run (driver's check);
  a start outside the rule, or while charging;
  the phone leaving during the run (no line);
  a line whose settings differ from the queue's.
  Excluded runs keep their raw lines and are listed with the reason.

thermal logging
  Battery and skin temperature and thermal status before, every 15 s during, and after each run, with host UTC
  times. Aligned to phase_start_s by the logcat time of the result line (or by a wall-clock field if the fixed
  commit prints one). Reported: thermal status and skin temperature at the start of the index, edits and
  queries phases, and the number of samples at status 1 or above per phase.

reported per configuration (fixed now)
  edit_total p50 and p95, per run and pooled over runs, overall and by token length, against 200 ms;
  query_embed and query_hybrid p95 at the store size the line reports;
  mem_lifecycle_peak_kb in KiB and decimal MB against 488,281 KiB, stated as a sampled test-process peak;
  index_total_ms per run, against 300 s; every run listed, with range.
  Three or four runs per configuration give no useful interval; differences between A and B under 10% are
  called inconclusive. The targets are judged per run and all runs are shown.

optional parts
  step 4 (owner's choice; quality INCONCLUSIVE, labelled so in every table): C model=bge-fp32+maxTokens=128,
    D model=minilm-fp32+maxTokens=256, E model=minilm-fp32+maxTokens=128; blocks of three runs in the orders
    CDE, DEC, ECD; same rule, same exclusions.
  step 5: step 3 on the Pixel 4 XL with the same baseline procedure on that phone (sensor sdm-therm-monitor);
    reported separately, never pooled.

not covered by these runs: whole-app memory, screen-off and background runs, energy.
